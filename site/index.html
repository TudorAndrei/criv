criv

criv is an open-source Rust CLI that keeps repository documentation connected to the code it describes. Docs point at real files, symbols, and decisions; criv checks that those references still resolve before a change lands. It runs locally, with no server and no network access.

Install criv

With a Rust toolchain:

cargo install --git https://github.com/TudorAndrei/criv criv

Or pin a released binary with mise, so the whole project runs one version. In mise.toml: 

[tools."github:TudorAndrei/criv"]
version = "0.7.0"
mise install

Add criv to a new codebase

Four commands, from the root of the repository you want to document:

criv init                    # create criv.toml, docs/, docs/adr/, Git hooks
echo '.criv/' >> .gitignore   # generated state stays local
criv watch --once            # build the graph
criv check                   # validate it

criv init writes only what it needs and leaves existing Markdown alone. It also installs pre-commit and pre-push hooks; existing hooks are preserved unless you pass --force-hooks. Skip parts with --no-hooks, --no-skills, --no-obsidian, or --no-vscode.

Everyday commands

criv check --fix                   # apply Markdown fixes
criv query coverage                # what is documented, what is not
criv query governing src/main.rs   # which ADRs govern this file
criv search --grep "watch --once"  # search code and notes
criv enforce --stage ci            # same gate the hooks run

Questions

Does criv replace my linter or my docs site?

No. criv validates the relationship between docs and code. Linters, source control, and your editor keep doing their jobs.

Does it send anything over the network?

No. Everything runs locally. Generated state lives in .criv/ and is meant to stay out of version control.

What does criv check actually validate?

Markdown formatting, note schema, ADR placement, wiki-links, source targets, Mermaid C4 diagram references, policy pattern references, and ADR supersession rules.
