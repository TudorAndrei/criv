# Do Not Track Generated Plugin Bundles

## Context

[[0009-obsidian-plugin-as-state-consumer|ADR-0009]] established the Obsidian
plugin as a local UI over criv state. [[0021-audit-remediation-boundaries|ADR-0021]]
then treated the plugin as a maintained product surface and assumed the
repository would track both plugin source and generated artifacts.

That assumption is too broad. The Obsidian plugin bundle
`.obsidian/plugins/criv/main.js` is generated by `.obsidian/plugins/criv/esbuild.config.mjs`
from authored TypeScript under `.obsidian/plugins/criv/src/`. The esbuild
configuration writes `main.js` as its `outfile` and adds a generated-file
banner telling maintainers to edit `src/main.ts` instead.

Tracking this bundle creates two problems:

- It makes code review and documentation indexing treat generated output as
  maintainable source.
- It lets criv source graph queries parse bundled JavaScript symbols that do
  not represent authored architecture.

## Decision

Do not track generated Obsidian plugin bundles.

The repository should track authored plugin source, build configuration,
fixtures, package metadata, and tests. Generated outputs such as
`.obsidian/plugins/criv/main.js` and WASM package output under
`.obsidian/plugins/criv/pkg/` should be ignored and regenerated by the plugin
build.

`package.json` may continue to name `main.js` as the Obsidian plugin entrypoint
because Obsidian loads the built bundle. That runtime entrypoint does not imply
that the bundle belongs in version control.

criv source indexing should follow the same source/artifact boundary: index
authored plugin files and exclude generated plugin outputs, either through
`.gitignore`, `criv.toml` source exclusions, or both.

## Consequences

Plugin release and local development workflows must run the plugin build before
using or packaging the Obsidian plugin.

Diffs become smaller and source graph output becomes cleaner because generated
bundle symbols are absent.

Reviewers should treat changes to `.obsidian/plugins/criv/src/**`,
`.obsidian/plugins/criv/esbuild.config.mjs`, `crates/criv-wasm/**`, and package
metadata as the authoritative plugin changes. Generated `main.js` diffs should
not be used as review evidence.

This narrows the generated-artifact assumption in
[[0021-audit-remediation-boundaries|ADR-0021]] while preserving its core
decision: the Obsidian plugin remains a maintained criv product surface with
pinned dependencies and repository-level validation.
