# Init Ships Plugin Source Not Generated Bundle

## Context

[[0023-do-not-track-generated-plugin-bundles|ADR-0023]] established that the
Obsidian plugin bundle `.obsidian/plugins/criv/main.js` is generated by esbuild
from authored TypeScript and should not be tracked as source.

`criv init` still embedded that generated bundle with `include_str!`, which
made fresh checkout builds depend on an ignored local artifact. That contradicted
the generated-artifact boundary and caused release builds from a clean checkout
to fail before compilation.

## Decision

`criv init` should install authored Obsidian plugin source, styles, tests,
fixtures, package metadata, and build configuration. It should not install the
generated `main.js` bundle.

Users who want to load the plugin after initialization must run the plugin build
to generate `main.js` from the installed source. The plugin manifest can still
name `main.js` as the Obsidian runtime entrypoint because it is the built output,
not the source template.

## Consequences

The Rust binary can be built from a clean source checkout without generated
plugin artifacts present.

Initialized vaults contain the source needed to build the plugin, but not a
prebuilt plugin bundle. This keeps generated JavaScript out of source control
and out of embedded Rust templates.
