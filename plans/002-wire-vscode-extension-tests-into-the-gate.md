## Why this matters

The VS Code extension has 8 unit-test files under
`extensions/vscode-criv/test/unit/` — including regression tests for a recent
security fix (source-target path bounding) and preview-helper parity tests —
but no hook and no CI step ever runs them. The Obsidian plugin's tests DO run
in the gate (`plugin-test` step), so this is an asymmetry, and tests that never
run rot: the modules they cover can regress while `mise run check` and CI stay
green. The fix is pure wiring in `hk.pkl`; CI already installs the extension's
npm dependencies.

## Current state

Relevant files:

- `hk.pkl` — hk hook configuration (pkl format). Defines local steps then
  assigns them to hooks (`pre-commit`, `pre-push`, `check`, `fix`).
- `mise.toml` — already defines the runnable tasks: `vscode-test` runs
  `npm --prefix extensions/vscode-criv test`, and `vscode-format-check` runs
  `npm --prefix extensions/vscode-criv run format:check`.
- `.github/workflows/ci.yml` — runs `xvfb-run -a mise run check` after
  `npm --prefix extensions/vscode-criv ci`, so any step added to the `check`
  hook automatically runs in CI. **Do not edit this file.**

`hk.pkl` already defines a shared glob list and the extension's existing steps
(around lines 68–92):

```pkl
local vscode_files = List(
  "extensions/vscode-criv/package.json",
  "extensions/vscode-criv/package-lock.json",
  "extensions/vscode-criv/tsconfig.json",
  "extensions/vscode-criv/**/*.ts",
  "extensions/vscode-criv/**/*.mjs",
  "extensions/vscode-criv/**/*.json",
  "extensions/vscode-criv/test/**/*.ts",
  "extensions/vscode-criv/scripts/**/*.mjs",
  "crates/criv-wasm/**",
  "mise.toml",
)

local vscode_lint = new Step {
  glob = vscode_files
  check = "mise run vscode-lint"
}
```

The Obsidian plugin's equivalent steps (the pattern to copy, ~lines 48–66):

```pkl
local plugin_test = new Step {
  glob = plugin_files
  check = "mise run plugin-test"
}
```

Hook assignments as they exist today (~lines 125–166): the `pre-commit` hook
lists `vscode-lint` and `vscode-json-diagnostics`; the `pre-push` hook lists
`cargo-clippy`, `cargo-test`, `criv-enforce`; the `check` hook lists (among
others) `plugin-format-check`, `plugin-lint`, `plugin-test`, `plugin-build`,
`vscode-lint`, `vscode-json-diagnostics` — but no `vscode-test` and no
`vscode-format-check` anywhere.

What `mise run vscode-test` does (from `extensions/vscode-criv/package.json`):
`npm test` = `npm run compile && npm run compile:unit-tests && node --test
dist-test/unit/*.test.js`. It typechecks (`tsc --noEmit`), bundles, and runs
node's test runner — no display server needed (the integration tests, which do
need one, are a separate `test:integration` script already wired as
`vscode-json-diagnostics`).

Precondition for running locally: `npm --prefix extensions/vscode-criv ci`
(or `install`) must have been run once so `node_modules` exists. The repo
checkout you work in already has `extensions/vscode-criv/node_modules/`.

## Steps

### Step 1: Establish the baseline

Run `mise run vscode-test` and `mise run vscode-format-check` before touching
anything.

**Verify**: both exit 0. If either fails, STOP — the point of this plan is to
wire in passing tests, and a pre-existing failure needs a human decision.

### Step 2: Define the two new steps in `hk.pkl`

Next to the existing `vscode_lint` step definition, add:

```pkl
local vscode_test = new Step {
  glob = vscode_files
  check = "mise run vscode-test"
}

local vscode_format_check = new Step {
  glob = vscode_files
  check = "mise run vscode-format-check"
}
```

### Step 3: Assign the steps to hooks

- In the `check` hook's `steps` block, add
  `["vscode-format-check"] = vscode_format_check` and
  `["vscode-test"] = vscode_test`, next to the existing `vscode-lint` entry
  (mirroring how `plugin-format-check` / `plugin-test` sit next to
  `plugin-lint`).
- In the `pre-push` hook's `steps` block, add `["vscode-test"] = vscode_test`
  after `cargo-test`.
- Do NOT add `vscode-test` to `pre-commit` — it compiles the whole extension
  and would slow every commit; lint already runs there. (The Obsidian plugin
  tests are likewise check/CI-only today.)

**Verify**: `mise run check` → exit 0, and its output lists `vscode-test` and
`vscode-format-check` among the executed steps.

### Step 4: Commit

**Verify**: `git diff --stat` shows only `hk.pkl` changed.

**Commit**: `ci(hooks): run vscode extension tests in the check gate`
