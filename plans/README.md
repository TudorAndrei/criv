## Findings considered and rejected

Recorded so the next audit doesn't re-derive them:

- **Transitive crate-version duplicates** (rand ×3, phf ×4, indexmap, etc.):
  all originate in independent upstreams (rumdl, ast-grep, fff-search,
  usage-lib); criv controls none of them. Not actionable. (The one criv CAN
  remove — direct git2 — is plan 010.)
- **fff-search → git2 0.20.4 / bincode advisories**: documented monitor-only
  posture in `docs/dependency-evaluations.md` (2026-07-01); not re-reported.
- **Mermaid SVG `innerHTML` insertion** (both editors): guarded by Mermaid
  `securityLevel: "strict"`; re-checked, no new bypass found.
- **`git show` argument handling** in query/enforce: args go directly to
  `Command`, no shell; re-checked, fine.
- **Obsidian DOT sanitizer `<style>`/CSS gap** (`core.ts:197-208` renders
  into a CSP-less Electron DOM via `main.ts:943`): LOW confidence — requires
  proving Graphviz output can carry attacker-influenced `<style>` from `.c4`
  source. Left as an OPEN INVESTIGATION, not a plan; pick it up alongside
  plan 004's webview work if someone wants to close it.
- **hk step merge of criv-check + criv-enforce**: rejected in favor of plan
  007 — `enforce` does not subsume `check` (markdown format, C4-interface
  drift, and vault-wide policy scans differ), so merging hook steps would
  change behavior.
- **README prose polish beyond the query-token mismatch**: not worth doing;
  the mismatch itself is in plan 013.
